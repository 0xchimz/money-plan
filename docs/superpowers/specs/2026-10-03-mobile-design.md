# money-plan บนมือถือ — design spec

> วันที่: 3 Oct 2026 · สถานะ: **Chin อนุมัติ design ในแชท 3 Oct ("โอเค ทำเลย")** · ที่มา: brainstorming 3 Oct · mockup ที่เลือกแล้วอยู่ใน `2026-10-03-mobile-mockups/` (`mobile-directions.html` = 3 ทิศทาง เลือก **B**, `mobile-b-screens.html` = จอที่เหลือของ B, Chin โอเคทั้ง 6 จอ) · แก้ข้อ "desktop อย่างเดียว" ใน `2026-09-29-money-plan-design.md` §1

## 1. เป้าหมายและขอบเขต

ให้ทุกอย่างที่ทำได้บน desktop ทำบนมือถือได้ด้วย: ดู Overview, กรอกและปิดเดือน Balance, แก้ Planning · Nitcha ใช้มือถือเป็นหลัก

**ถือว่าเสร็จเมื่อ**
- บน iPhone จริง: Add to Home Screen → เปิดจาก icon (ไม่มีแถบ Safari) → login ด้วย Google → ปิดเดือน Balance ได้ครบ flow → เปิด Overview อ่านได้โดยไม่ต้องซูมหรือเลื่อนจอไปด้านข้าง
- ที่ 360 / 390 / 768px ไม่มีหน้าไหนเลื่อนแนวนอนได้ (ยกเว้นแถบที่ตั้งใจให้ปัด)
- ที่ 1024 / 1440px หน้าตาเหมือนก่อนแก้ (เทียบ screenshot ก่อน-หลัง)
- `pnpm typecheck`, `pnpm test`, `pnpm lint`, `pnpm build` ผ่าน

**ไม่อยู่ในงานนี้**: offline / service worker, ปุ่มสลับธีม (ธีมยังตามเครื่อง), ฟีเจอร์หรือ API ใหม่ (ยกเว้น §6 ถ้าจำเป็น), ปัดซ้าย-ขวาเปลี่ยนหน้า, native app

## 2. แบ่งจอ

| กว้าง | โหมด |
| --- | --- |
| < 1024px | **มือถือ** (แบบ B) — รวม iPad แนวตั้ง · เนื้อหากว้างไม่เกิน 640px จัดกลางจอ |
| ≥ 1024px | **desktop** เหมือนเดิมทุกอย่าง |

จุดตัดเดียวคือ 1024px (Tailwind `lg`) ซึ่ง spec v1 ใช้เป็นขอบ desktop อยู่แล้ว จึงไม่มี layout ที่ 3 สำหรับ tablet

## 3. โครงสร้าง code

**หน้าเดิม สลับเฉพาะส่วนที่ต่าง**
- `src/lib/use-is-mobile.ts` — `useIsMobile()` = `matchMedia('(max-width: 1023.98px)')` ฟังการเปลี่ยนขนาดจอ
- state, การโหลดข้อมูล และ `mutate()` อยู่ที่ page component เดิมที่เดียว · ส่วนที่หน้าตาต่างกัน (แถว, Sankey, ตาราง, แถบร่าง) page เลือก render ตัว desktop หรือตัวมือถือจาก `useIsMobile()` แล้วส่ง callback ชุดเดียวกันให้
- การเรียงการ์ดลงมาเป็นคอลัมน์เดียวใช้ class `lg:` ของ Tailwind (desktop ขึ้น `lg:` ทั้งหมด จึงเหมือนเดิม)
- ชิ้นที่ใช้ร่วม: `src/components/mobile/` — `sheet.tsx` (แผ่นเลื่อนขึ้น), `bottom-nav.tsx`, `top-bar.tsx`, `amount-field.tsx`, `account-sheet.tsx`
- ชิ้นเฉพาะหน้า: `src/pages/balance-mobile.tsx`, `planning-mobile.tsx`, `overview-mobile.tsx` (`balance.tsx` ยาว 927 บรรทัดแล้ว ไม่เพิ่มเข้าไปอีก) · ถ้าต้องใช้ component ที่อยู่ในไฟล์ page เดิม (เช่น `InvestFields`, `Change`) ให้ export ออกมาใช้ ไม่ copy
- logic ที่ไม่ใช่ UI แยกเป็นฟังก์ชันล้วนใน `src/lib/` มี unit test (§8)

**แผ่นเลื่อนขึ้น** = `Drawer` ของ `@base-ui/react` 1.8 (ติดตั้งอยู่แล้ว ไม่ลง package ใหม่) — ปัดลงเพื่อปิด, แตะพื้นหลังเพื่อปิด, ใช้ `Drawer.VirtualKeyboardProvider` ยกแผ่นพ้นคีย์บอร์ด iPhone · มีหัวแผ่น (title) ทุกแผ่นเพื่อ accessibility

## 4. Layout ทุกหน้า (โหมดมือถือ)

- **แถบบน** (`top-bar.tsx`, sticky): ชื่อหน้า + ข้อมูลเสริมของหน้า + รูปโปรไฟล์ขวาสุด · เว้น `env(safe-area-inset-top)`
  - Overview: "ภาพรวม · ปิดล่าสุด ก.ย. 2026"
  - Planning: "แผนเงิน" + ปุ่มชุดงบ (ปัจจุบัน / Projection / ตกงาน) เต็มความกว้าง ติดใต้แถบบน
  - Balance: ‹ เดือน › + badge ร่าง/ปิดแล้ว + ชิปเรท "USD 32.39 ✓" (ยังไม่ยืนยัน = จุดเหลือง, ไม่มีแถว USD = ไม่แสดง)
- **แถบเมนูล่าง** (`bottom-nav.tsx`, fixed): ภาพรวม / แผนเงิน / งบดุล + icon (lucide) · เว้น `env(safe-area-inset-bottom)` · เนื้อหาเว้นด้านล่างพอไม่ให้ถูกบัง
- **รูปโปรไฟล์** → แผ่นบัญชี: รูป ชื่อ อีเมล + "ออกจากระบบ"
- **toast** (sonner) ขึ้นด้านบนในโหมดมือถือ
- ปุ่ม/จุดแตะทุกอันสูงอย่างน้อย 44px · ช่องพิมพ์ทุกช่องตัวอักษร ≥ 16px (iPhone จะไม่ซูมจอเอง)
- หน้า login: การ์ดกลางจอเดิม ปรับ padding ให้พอดี 360px · ไม่มีแถบบน/ล่าง

## 5. แต่ละหน้า (โหมดมือถือ)

### 5.1 Balance — mockup รอบ 1 จอ B2, B3 · รอบ 2 จอ 3, 4

**ลิสต์**
- การ์ดหมวดเดิม: icon + ชื่อไทย + "N / M เช็กแล้ว" + ยอดรวมหมวด (+ แถบเทียบเป้าถ้ามี) · ปุ่ม "ยืนยันทั้งหมวด" อยู่ในหัวการ์ดเหมือนเดิม
- แถว: วงกลมยืนยัน (แตะได้ตรงๆ พื้นที่แตะ 44px) · ชื่อ + บรรทัดรอง (เดือนก่อน / ≈ THB ของแถว USD / tier / "ไม่ได้นับในพอร์ต — จัดกลุ่ม") · ยอด + ส่วนต่างใต้ยอด · แตะส่วนอื่นของแถว → **แผ่นแก้ยอด**
- ชิปรายการยอดนิยม + "เพิ่มเอง" ยังอยู่ท้ายการ์ด · หมวดว่างยุบบรรทัดเดียวเหมือนเดิม
- การ์ดสรุป (net worth, พอร์ต, EF, เปลี่ยนเพราะอะไร, กราฟ, รายการที่ซ่อน) เรียงต่อท้ายเป็นคอลัมน์เดียว

**แผ่นแก้ยอด** (แถวที่มีอยู่)
- หัว: ชื่อรายการ · หมวด · "แถว k จาก n ที่ยังไม่เช็ก" (เฉพาะร่าง) · ปุ่ม ฿ THB / $ USD
- ยอดเดือนก่อน · **ช่องยอดใหญ่** (`amount-field.tsx`): `inputMode="decimal"` + แถวปุ่ม **+ − × ÷** ใต้ช่อง (คีย์บอร์ดตัวเลข iPhone ไม่มีเครื่องหมาย) · แสดง "= ผลลัพธ์" + ส่วนต่าง · สูตรเก็บใน `expr` เหมือนเดิม
- ปุ่ม (ร่าง): **✓ ยอดไม่เปลี่ยน** (ยืนยันโดยไม่แก้) · **บันทึก · ถัดไป ›** (บันทึก แล้วยืนยัน แล้วเปิดแถวถัดไป) · เดือนที่ปิดแล้ว: ปุ่มเดียว **บันทึก**
- "ถัดไป" = แถวที่ยังไม่ยืนยันแถวแรกหลังแถวนี้ตามลำดับบนหน้า (สินทรัพย์ → หนี้สิน, หมวดตามลำดับคงที่, แถวตามลำดับในหมวด) ถ้าหลังแถวนี้ไม่มีแล้วให้วนกลับไปดูจากต้น · ไม่เหลือเลย → ปิดแผ่นแก้ยอด แล้วเปิดแผงปิดเดือน
- ลิงก์ล่าง: "จัดกลุ่มการลงทุน" (สินทรัพย์เท่านั้น → ฟิลด์ tier/ประเภท/ประเทศในแผ่นเดียวกัน) · "ซ่อนรายการนี้"

**แผ่นเพิ่มรายการ** (จากชิปหรือ "เพิ่มเอง"): ชื่อ · ยอด + ฿/$ · สวิตช์นับเป็นพอร์ตลงทุน → tier 4 ปุ่ม (มีคำอธิบายสั้น) / ประเภท / ประเทศ · ใช้ค่าเดาเดิม (`guess`, `guessCurrency`) · "เพิ่มเอง" ระดับฝั่ง (`AddItem`) มีช่องเลือกหมวดด้วย

**แถบปิดเดือนลอย** (ร่างเท่านั้น, อยู่เหนือเมนูล่าง): "เช็ก x / y · โอน a / b" + progress + ปุ่มปิดเดือน · แตะแถบ → **แผงปิดเดือน**
- เรท USD/THB (ยืนยันแล้ว / ยังเป็นของเดือนก่อน → แตะเปิดแผ่นเรท)
- ยังไม่เช็ก N รายการ → "ไล่เช็กต่อ ›" เปิดแผ่นแก้ยอดแถวแรกที่ค้าง
- ลิสต์โอนเงินรายธนาคาร (ติ๊ก, แตะยอดเพื่อคัดลอก, บัญชีย่อย, รวม/เหลือโอน, รายการที่ไม่ต้องโอน) = เนื้อหาเดียวกับ `TransferCard`
- ปุ่ม **ปิดเดือน** (ยังมีของค้าง → ถามยืนยันเหมือน `DraftBar`) · "ลบร่างเดือนนี้" (ถามยืนยันก่อนลบ)
- ร่างที่ยังไม่มีแถว: ปุ่มปิดเดือนกดไม่ได้ + "เพิ่มอย่างน้อย 1 รายการก่อนปิดเดือน"

**เดือนที่ปิดแล้ว**: แถบลอยเป็นปุ่ม "เริ่มปิดบัญชี {เดือนถัดไป}" (ถ้าเริ่มได้) หรือ "ไปที่ร่างที่เปิดอยู่" · ไม่มีอะไรให้ทำ = ไม่มีแถบ

**แผ่นเรท**: ช่องเรท (4 ทศนิยม) + ปุ่มใช้เรท ECB (ถ้ามี) + ปุ่มยืนยัน — logic เดียวกับ `FxRate`

**ยังไม่มีงบดุลเลย**: `StartCard` เดิมเต็มความกว้าง

### 5.2 Planning — mockup รอบ 2 จอ 1, 2

- ปุ่มชุดงบติดใต้แถบบน (§4) · note ของชุดงบอยู่ใต้ปุ่ม
- hero: ออมและลงทุนต่อเดือน + % ของรายรับ + แท่งสัดส่วน (รายจ่าย / ลงทุน / ออม / ยังไม่จัดสรร) + ข้อความเตือนยังไม่จัดสรร/จัดสรรเกิน · "เงินออมไปที่ไหน" ต่อใต้ hero
- ตัวชี้ (DSR, ตกงานอยู่ได้) เป็นการ์ดแถวเดียว **ปัดซ้าย-ขวา** (scroll-snap)
- 3 section (รายรับ / ออมและลงทุน / รายจ่าย): หัว section เดิม · หัวหมวดย่อย · แถว = ชื่อ + บัญชี (บรรทัดรอง) + ยอด + › · แตะแถว → **แผ่นแก้รายการ**
- **แผ่นแก้รายการ**: ชื่อ · บัญชี/ที่มาเงิน (ไม่บังคับ) · หมวด = ชิปหมวดที่มีใน section + "หมวดอื่น…" พิมพ์เองได้ · ยอดต่อเดือน (`amount-field`, ≥ 0) + "% ของรายรับ" · ปุ่มยกเลิก / บันทึก · "ลบ" มุมขวาบน → ลบทันที + toast เลิกทำ (เหมือนเดิม)
- ชิป "+ ชื่อ" / "เพิ่มเอง" → แผ่นเดียวกันในโหมดเพิ่ม กรอกชื่อ/หมวดไว้ให้
- ท้ายหน้า: รายจ่ายตามหมวด, เทียบทุกชุดงบ (ตารางเดิม 4 คอลัมน์ ตัวเลขย่อขนาดตัวอักษรให้พอดี 360px โดยไม่ย่อเลข)
- ชุดงบว่าง (`EmptyScenario`) เต็มความกว้าง

### 5.3 Overview — mockup รอบ 1 จอ B1 · รอบ 2 จอ 5, 6

- hero net worth เดิม (sparkline + สรุป N เดือน) เต็มความกว้าง
- 3 ตัวชี้: ออม+ลงทุน / EF / หนี้ต่อสินทรัพย์ → grid 2 คอลัมน์ ตัวที่ 3 เต็มแถว
- **เงินเดือนไปไหน**: Sankey → **แท่งสัดส่วน + ลิสต์** (`FlowBars`): ปุ่มสลับชุดงบเดิม · รายรับรวม · แท่ง (รายจ่าย / ลงทุน / ออม / ยังไม่จัดสรร) · ลิสต์ 4 กลุ่ม แตะกลุ่ม → กางรายการย่อย (รายจ่าย = หมวด, ออม/ลงทุน = รายการ) ข้อมูลชุดเดียวกับ Sankey · จัดสรรเกิน → คำเตือนแทนแท่ง "ยังไม่จัดสรร" · ปุ่ม "แก้ใน Planning →"
- กราฟสินทรัพย์ vs หนี้ / สัดส่วนสินทรัพย์ตามเวลา: เต็มความกว้าง แสดง 6 เดือนล่าสุด ที่เหลือปัดดูย้อนหลัง (container scroll แนวนอน เริ่มที่เดือนล่าสุด) · ปุ่ม Chart / Table เดิมยังอยู่
- เดือนนี้เปลี่ยนเพราะอะไร, พอร์ตเทียบเป้า, ตามประเภท / ประเทศ / top holdings เรียงคอลัมน์เดียว
- แก้เป้า tier → **แผ่น** (4 ช่อง % รวม 100%)
- **Balance sheet** → ลิสต์พับได้: สินทรัพย์ (กางไว้ แสดง 3 หมวดใหญ่สุด + "ดูทั้งหมด") / หนี้สิน (พับ) / ความมั่งคั่งสุทธิ · แตะหมวด → รายการในหมวด
- Onboarding (ยังไม่มีเดือนปิด): checklist 3 ขั้นเรียงแนวตั้ง, การ์ด "หน้านี้จะมีอะไร" ต่อท้าย, โครงกราฟจางเต็มความกว้าง

## 6. Add to Home Screen

- `public/manifest.webmanifest`: `name` "money-plan", `display: "standalone"`, `start_url: "/"`, `background_color` / `theme_color` = `#f6f2ea`, icons 192 / 512 (+ maskable 512)
- `public/apple-touch-icon.png` 180×180 · ไฟล์ PNG ทั้งหมดทำจาก `favicon.svg` เดิม (สคริปต์ครั้งเดียว commit ไฟล์ผลลัพธ์)
- `index.html`: `<link rel="manifest">`, `<link rel="apple-touch-icon">`, `<meta name="apple-mobile-web-app-capable" content="yes">`, `<meta name="mobile-web-app-capable" content="yes">`, `apple-mobile-web-app-status-bar-style` = `default`, `theme-color` แยกสว่าง/มืด (`media="(prefers-color-scheme: dark)"` = `#171411`), `viewport` เพิ่ม `viewport-fit=cover`
- ไม่มี service worker · Worker เสิร์ฟไฟล์ใน `public/` เป็น static assets อยู่แล้ว (เช็กว่า `/manifest.webmanifest` ไม่ตกไปที่ SPA fallback)
- iPhone: แอปจาก home screen แยก cookie จาก Safari → login ในแอปอีก 1 รอบ (จำ 30 วัน)

**⚠️ ความเสี่ยง: ปุ่ม Google แบบ popup ในแอปจาก home screen บน iPhone** — ทดสอบเป็นงานแรก (deploy เฉพาะส่วน §6 แล้ว Chin ลองบน iPhone)
- ผ่าน → ใช้ popup ต่อ
- ไม่ผ่าน → เปลี่ยนเป็นโหมด redirect ของ Google Identity Services ใน standalone เท่านั้น: `ux_mode: 'redirect'`, `login_uri` = `/api/auth/google/redirect` (endpoint ใหม่รับ form POST `credential` + `g_csrf_token`, ตรวจ `g_csrf_token` ตรงกับ cookie ชื่อเดียวกัน = double-submit, ตรวจ token แบบเดียวกับ `/api/auth/google`, ตั้ง session แล้ว redirect `/`; อีเมลไม่อยู่ใน allowlist → redirect `/?denied=<email>`) · endpoint นี้ยกเว้นกฎ JSON-only ได้เพราะมี csrf token ของ Google คุ้ม · ต้องเพิ่ม `login_uri` ใน OAuth client (Chin ทำใน Google Cloud console) · มี test ฝั่ง worker

## 7. Error handling

ไม่เปลี่ยน: บันทึกไม่ได้ → toast + โหลดข้อมูลใหม่เหมือนเดิม · แผ่นแก้ยอดปิดเฉพาะเมื่อบันทึกสำเร็จ (บันทึกไม่ได้ → แผ่นยังเปิด ค่าที่พิมพ์ยังอยู่) · 401/403 ระหว่างเปิดแผ่น → ไปหน้า login ตามเดิม
